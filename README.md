# NoShowRadar

NoShowRadar is a Python data-analysis and machine-learning project that explores missed medical appointments in a public dataset and presents appointment-level risk scores in a Streamlit dashboard.

The project is an educational analysis tool, not a clinical system. Its risk scores should not be used to make healthcare decisions.

## What the project does

- Audits and cleans the appointment records, reporting every removed row.
- Engineers lead-time, weekday, age-group, and wait-band features.
- Loads the cleaned records into SQLite and runs reusable SQL analyses.
- Visualizes no-show rates by waiting time, age group, weekday, and SMS status.
- Compares a majority-class baseline, logistic regression, and random forest.
- Provides an interactive dashboard for exploring results and trying example appointment inputs.

## Dataset

The source is Kaggle's **Medical Appointment No Shows** dataset, containing appointment records from municipal clinics in Vitoria, Brazil. Download the CSV from Kaggle yourself and place the single CSV file in the project's `data/` directory. The raw dataset is excluded from Git.

The repository includes the cleaned CSV and generated analysis outputs so the reported results can be inspected without downloading the raw file. The SQLite database and serialized model are local generated files and are excluded from Git.

## Run locally

Use Python 3.11 or newer. From PowerShell:

```powershell
git clone https://github.com/RajKiranAcharyya/NoShowRadar-.git
Set-Location NoShowRadar-
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
New-Item -ItemType Directory -Force data | Out-Null
```

Download the Kaggle CSV into `data/`, then run the pipeline from the project root:

```powershell
python clean.py
python build_database.py
python run_queries.py
python charts.py
python train.py
streamlit run app.py
```

The final command opens the dashboard in your browser. The app expects the charts, model results, and trained model generated by the preceding steps.

## Results

All numbers below come from the checked-in cleaning, SQL, and model output files. The model metrics are for one stratified 80/20 split by appointment record.

### Cleaning

| Measure | Records |
| --- | ---: |
| Raw appointments | 110,527 |
| Removed: invalid age | 6 |
| Removed: appointment date before scheduled date | 5 |
| Removed: duplicate appointment ID | 0 |
| Removed: missing values | 0 |
| Cleaned appointments | 110,516 |

### Exploratory analysis

- Overall no-show rate: **20.2%**.
- Same-day appointments had a **4.6%** no-show rate; appointments scheduled 31 or more days ahead had a **33.0%** rate.
- The 13–18 age group had the highest observed age-band rate (**26.1%**); the 66+ group had the lowest (**15.5%**).
- Recorded SMS recipients had a **27.6%** no-show rate, compared with **16.7%** among non-recipients. This is an association, not evidence that reminders increase no-shows: reminders may be targeted to appointments already considered higher risk.

### Model comparison

The positive class is a missed appointment (`no_show = 1`).

| Model | Accuracy | Precision | Recall | F1 |
| --- | ---: | ---: | ---: | ---: |
| Majority-class baseline | 79.81% | 0.00% | 0.00% | 0.0000 |
| Logistic regression | 66.27% | 31.33% | 56.28% | 0.4025 |
| Random forest | 57.96% | 30.30% | 83.28% | 0.4444 |

The random forest favors recall: on this test split it detected 3,716 of 4,462 no-shows, with 8,547 false positives. Accuracy alone is misleading for this imbalanced dataset; the majority-class baseline appears accurate while detecting no missed appointments.

The random forest's reported feature importances are led by `wait_days` (78.4%), `age` (10.5%), and `sms_received` (5.9%). Feature importance describes the fitted model and does not establish causation.

## Limitations and responsible interpretation

- The split is by appointment, not by patient. Patients with multiple visits can appear in both training and test sets, so the reported metrics do not measure performance on entirely unseen patients and may be optimistic.
- Model selection uses F1 from the same held-out split reported above. A patient-grouped validation process and a separate final test set would provide a stronger estimate.
- Balanced class weights make the dashboard's `predict_proba` output an uncalibrated model score, not a reliable real-world probability.
- Precision is modest, and the selected model produced many false positives in the reported test split.
- The dataset comes from one region and period; performance may not generalize to another clinic or population.
- The weekday analysis has very few Saturday records and no Sunday appointments. Treat those weekday comparisons cautiously.
- The charts show associations, not clinical or behavioral causation. This project is for learning and demonstration, not diagnosis, patient prioritization, or automated healthcare decisions.
